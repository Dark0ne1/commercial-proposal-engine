# Границы безопасности

Сервис рассчитан на изолированное демонстрационное рабочее место или
внутренний доступ через защищённый reverse proxy. Все пользователи здесь —
менеджеры одного поставщика, tenant isolation и разграничения между менеджерами нет.

Пароль PBKDF2-SHA256, 600000 итераций, отдельная случайная соль. Случайный
токен сессии хранится в cookie HttpOnly/SameSite=Strict; в БД только SHA256.
Срок 8 часов, logout отзывает токен. Secure включать за HTTPS.
Origin проверяется для browser mutations, CORS не разрешён. Нет Origin
допускается для серверных клиентов с cookie. Вход и документы не кешируются.
Только для локального HTTP PUBLIC_ORIGIN допускаются эквивалентные localhost
и 127.0.0.1 с тем же портом. Публичный Origin проверяется точным совпадением.
Не публиковать демо без HTTPS и rate limit /api/login; приложен Nginx пример.

Pydantic запрещает неизвестные поля, ограничивает длины и Decimal precision,
проверяет положительные количества. SQLAlchemy параметризует запросы;
поисковые %/_ экранированы. Файловые пути строятся из UUID БД и Literal
расширения; download требует авторизации и подтверждённой версии.
Рендерер не использует shell=True; LibreOffice получает только сгенерированный
внутренний DOCX, отдельный profile и timeout. Пользовательский DOCX не открывается
в LibreOffice: из него извлекается текст библиотекой python-docx.
Контейнеры API/UI/worker работают от непривилегированных пользователей.

Изменение цены/скидки в черновике требует явного подтверждения версии для
получения документов. Подтверждённая версия неизменна, ручная цена и исходная
каталоговая записаны в audit. Записи audit не криптографически защищены от DBA.
Отправки клиентам нет. Остатки не резервируются, наличие не коммерческая гарантия.

LLM boundary: входящий текст недоверенный. Разрешены только шесть Pydantic tools,
ни один не принимает SQL, Python, shell, URL, цену или произвольную скидку.
Клиент привязан к заявке, product_id должен быть результатом однозначного поиска.
Количество/единица/source проверяются по исходному тексту; пропуск SKU блокирует
черновик. Коммерческие параметры и характеристики копируются только из БД.
Final schema status=done проверяется; свободный текст модели не используется
в КП. Агент не умеет подтверждать и отправлять документы.

По умолчанию mock не делает сетевых вызовов. Compatible API конфигурируется
только оператором: пользователь не задаёт endpoint/model/key из формы.
Ключ — SecretStr, уходит только в Authorization header, не хранится в audit.
HTTP ошибки журналируются кодом без тела ответа и заголовков. Есть лимиты steps,
HTTP timeout, agent timeout и RQ hard job timeout. Redis — доверенная внутренняя
инфраструктура, порт наружу не опубликован. JSONSerializer используется вместо
pickle; Redis admin всё равно должен считаться привилегированным доступом.
DB lease/CAS и проверка claim token не дают старому worker выполнять tools.

Upload: максимум 10 МБ; MIME из браузера не считается доказательством типа,
расширение проверяется вместе со структурой ZIP/PDF. Исходники — content-addressed
SHA256, worker сверяет digest и путь. ZIP: максимум 1000 members / 30 МБ
распакованных данных, ограничение ratio, запрет DTD, encrypted ZIP и VBA.
XLSX: 10 листов, 1000 строк × 50 столбцов, 5000 ячеек, формулы отклоняются;
размеры считаются по содержимому, метаданным dimension не доверяем.
DOCX: только текст параграфов и таблиц. PDF: максимум 50 страниц, encrypted и
пустой текст отклоняются, OCR отсутствует. Общий извлечённый текст до 20000
символов. Разбор выполняет worker с RQ timeout и container memory limit 1 GB.
API proxy ограничивает JSON 256 КБ, multipart import 12 МБ с overhead формы.

Ограничения: нет MFA/SSO, восстановления пароля через UI, приложения rate limiter,
AV, квот файлов/документов, ротации audit и фонового render worker. Вывод DOCX/PDF
после подтверждения пока синхронный. Перед публичной эксплуатацией нужны
HTTPS/rate limits, проверка контейнеров и инфраструктуры, контроль disk usage.
