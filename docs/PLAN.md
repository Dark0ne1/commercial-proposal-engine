# План реализации

## 1. Вертикальный срез — реализован и проверен локально

С нуля: FastAPI / Pydantic 2 / SQLAlchemy 2 / Alembic / PostgreSQL;
Next.js / TypeScript / Tailwind; DOCX через python-docx, PDF через LibreOffice.

Область изменения: схемы API, доменный расчёт Decimal, модели и миграция,
сценарии заявки/версии/подтверждения, файлы, демоданные, UI, контейнеры,
тесты и документация. Существующих данных и вызывающих компонентов нет.

Готовность: менеджер входит, выбирает клиента, регистрирует текст заявки,
вручную выбирает позиции каталога, рассчитывает и редактирует черновик,
подтверждает конкретную версию, скачивает оба документа, видит журнал.
Повтор запросов не создаёт дубликаты; денежные поля проходят Decimal;
подтверждённая версия неизменна. Seed воспроизводим: 50/150/40/20.
Тесты расчёта, API, истории, повторов и документов; сборка UI.
Compose smoke проверяется только при наличии Docker; факт проверки фиксируется отдельно.

## 2. Агент и импорт — реализован и проверен

Явные Pydantic-инструменты search_catalog, get_customer, get_price,
check_availability, calculate_quote, create_quote_draft; настоящий ограниченный
tool-call цикл, OpenAI-compatible и mock провайдеры. XLSX/DOCX/PDF extraction,
уточнения, ручная проверка неоднозначностей, Redis/RQ, повтор задач и ошибки.
Готовность: 10 эталонных сценариев агента, ограничения и журнал tools/tokens,
полный автоматизированный путь от входящего документа до проверяемого черновика.

## 3. Эксплуатационное усиление

Проверенный запуск на Linux VPS, backup/restore, нагрузка и лимиты файлов,
проверка инфраструктуры и внешнего API только с отдельным разрешением.

В текущей версии UI явно показывает mock-провайдер, если выбран локальный режим.
Mock — ограниченный детерминированный разбор, не настоящая языковая модель;
оба провайдера используют один registry tools и один execution loop.
Отправка КП клиентам не реализуется. Инфраструктурный gate из этапа 3 остаётся
обязательным для заявления о полном завершении исходного ТЗ.
